Easy Lesson is a static site (HTML/CSS/JS + Markdown blog + build script). Deploy it to any static host. Pick one option below.

> **Important — run the build before every deploy:** Run `node build.js` before every deploy after adding or editing posts, because the blog listing, sitemap, and RSS feed are generated by the build. Deploying without rebuilding leaves the blog listing, sitemap, and RSS out of date.

## Option A — Vercel

1. **Import the folder.**
   - In the [Vercel dashboard](https://vercel.com/), choose **Add New → Project → Import**, and import the `easy-lesson-website` folder (from a connected Git repo, or via the Vercel CLI — see below).
   - Alternatively, from inside the project folder, run the CLI:
     ```bash
     vercel
     ```
     Follow the prompts to link/create the project, then deploy.
2. **Deploy.** Vercel builds and deploys the static site. Each later deploy: run `node build.js` first, then `vercel --prod` (or push to the connected repo, if using Git-based deploys).
3. **Attach a custom domain.**
   - In the project: **Settings → Domains** → add the real domain and follow Vercel's DNS instructions (see "Domain Setup" below).
4. **SSL is automatic.** Vercel provisions and renews the HTTPS certificate for the domain automatically. Verify the site loads over `https://`.

---

## Option B — Netlify

1. **Deploy the folder — pick one method:**
   - **Drag-and-drop:** In the [Netlify dashboard](https://app.netlify.com/), drag the `easy-lesson-website` folder onto the deploy area to publish it immediately.
   - **Connect a repo:** Choose **Add new site → Import an existing project**, connect the repo containing the site, and set the publish directory to the site folder. Netlify will redeploy on each push.
2. **Custom domain.**
   - In the site: **Site configuration → Domain management → Add a domain**, enter the real domain, and follow Netlify's DNS instructions (see "Domain Setup" below).
3. **HTTPS.** Netlify provisions a free HTTPS certificate for the custom domain automatically. Confirm the site loads over `https://` and that HTTPS is enforced (Netlify: **Domain management → HTTPS → Force HTTPS**).

---

## Option C — cPanel / Shared Hosting

1. **Build first.** Run `node build.js` in the project folder.
2. **Upload.** In cPanel File Manager (or via FTP), upload the **contents** of the `easy-lesson-website` folder — not the folder itself — into `public_html` (or the domain's document root if it differs).
3. **404 page.** The site ships a `404.html` file, which is served as the error page.
   - Most shared hosts serve `404.html` automatically. If a missing URL does not show your custom 404 page, set it explicitly in cPanel: **Advanced → Error Pages** → select the domain → choose **404 (Not Found)** → point it at `/404.html` → save.
4. **HTTPS.** Enable the free SSL certificate in cPanel (**Security → SSL/TLS Status → Run AutoSSL**, or your host's equivalent) and confirm the site loads over `https://`.

## Domain Setup (All Hosts)

1. **DNS.** At the domain registrar, point the domain to the host:
   - **Apex / root domain** (e.g. `example.com`): an **A record** to the host's IP address, as shown in the host's domain/DNS instructions.
   - **`www` subdomain:** a **CNAME record** pointing to the host's target hostname, as shown in the host's instructions.
   - Use exactly the DNS values your host (Vercel, Netlify, or cPanel host) gives you — they differ per host.
2. **Wait for propagation.** DNS changes can take minutes to a few hours to propagate worldwide.
3. **SSL / HTTPS check.** Once DNS resolves, confirm:
   - `https://` loads with no certificate warnings.
   - `http://` redirects to `https://`.
   - The certificate covers both the apex and `www` versions of the domain.

## Google Search Console

1. Add the site as a property in [Google Search Console](https://search.google.com/search-console/) using the real domain (URL-prefix property, `https://` version).
2. Verify ownership with the GSC verification meta tag placeholder in `seo-config.json`:
   - Copy the verification value Google Search Console gives you.
   - Replace the GSC verification placeholder in `seo-config.json` with that real value.
   - Rebuild (`node build.js`) and redeploy so the tag is live in the site's pages.
   - Click **Verify** in Search Console.
3. Submit the sitemap:
   - In Search Console, go to **Sitemaps** and submit `https://www.easylesson.example/sitemap.xml` — **replace `https://www.easylesson.example` with the real domain**.
   - Confirm the sitemap URL loads in a browser at the real-domain address.

## Bing Webmaster Tools

1. Add the site in [Bing Webmaster Tools](https://www.bing.com/webmasters/) using the real domain.
2. Verify ownership with the Bing verification placeholder (same pattern as GSC — replace the placeholder in `seo-config.json` with the real verification value Bing gives you, rebuild, and redeploy).
3. Submit the sitemap at the real-domain URL (`https://<real-domain>/sitemap.xml`).

## Post-Deploy Checklist

Run through this list after every deploy:

- [ ] **Tool iframe loads.** The Lesson Solver AI tool on the homepage (/#tool) loads and is usable.
- [ ] **All pages load.** Homepage, blog listing, every blog post, About, Contact, Privacy, Terms, Disclaimer, and 404 page all return successfully with no broken links.
- [ ] **Mobile check.** Open the homepage and at least one blog post on a phone-sized screen — layout, navigation, and tool are usable.
- [ ] **Sitemap reachable.** `https://<real-domain>/sitemap.xml` loads in a browser.
- [ ] **Robots.txt reachable.** `https://<real-domain>/robots.txt` loads in a browser.
- [ ] **HTTPS.** The site loads over `https://` with no certificate warnings, and `http://` redirects to `https://`.
- [ ] **Placeholders.** No visible placeholder content on the live site (contact email [CONTACT_EMAIL] and AdSense ID `ca-pub-XXXXXXXXXXXXXXXX` should be replaced with real values on the live site — see `adsense-guide.md` for the AdSense steps).
